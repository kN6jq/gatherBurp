> **文档版本**：v2.0（最终版）
> **生效日期**：2026-09-01
> **文档状态**：全项目注释整改唯一执行标准

## 一、文档概述

### 1.1 文档目的

统一 GatherBurp 项目全量 Java 源码的注释格式、话术、书写标准，解决以下现有问题：

- 新旧注释风格并存（规范 Javadoc 与逐字复述式行内注释混用）
- 中英文注释混用（`ScanTaskExecutor` 英文 Javadoc 与项目中文主调不一致）
- `@Author` / `@Date` 标签残留（`CustomScanIssue`、`SqlUI`、`GridBagConstraintsHelper` 等）
- DAO 层约 50% public static 方法缺 Javadoc
- UI 层 Entry/Model/Table 类缺类级注释
- Javadoc 块内空行冗余（`GridBagConstraintsHelper` 极端案例）
- 字段区行尾注释密度过高（`SqlUI` 每个字段跟 `// xxx`）
- 逐字复述式注释（`ExpressionUtils` 内 `// 获取请求url` 配 `getUrl()`）

提升项目可读性、可维护性、迭代统一性。

### 1.2 适用范围

`src/main/java` 下全部生产代码（`.java` 文件），覆盖：

| 分层 | 包路径 | 文件数（约） |
|------|--------|------------|
| 入口类 | `burp` | 1 |
| 实体 Bean | `burp.bean` | 12 |
| 数据 DAO | `burp.dao` | 10 |
| 菜单层 | `burp.menu` | 9 |
| UI 层 | `burp.ui`（含 `SimilarHelper`、`UIHelper`） | 39 |
| 工具层 | `burp.utils` | 30 |

测试代码（`src/test/java`）参照执行但不强制。

### 1.3 规范基准

本规范以项目现有 `docs/注释规范.md`（v1.0）为基础准则，以以下标杆文件的注释话术为格式参考锚点：

| 标杆文件 | 参考要点 |
|---------|---------|
| `BurpExtender.java` | 入口类生命周期注释、Burp API 约束注释、方法 Javadoc 首句行为说明 |
| `AbstractScanUI.java` | 抽象基类模板方法注释、线程模型（EDT/代理监听线程）、布局工具方法注释 |
| `SqlInjectionDetector.java` | 检测核心类无状态语义声明、方法 Javadoc 行为+返回值语义、行内注释解释判定逻辑 |
| `LruCache.java` | 并发工具类线程安全语义、锁纪律注释、容量淘汰规则注释 |
| `HostThrottle.java` | 限流策略注释、魔法数来源注释、TTL 过期逻辑注释 |
| `ConfigDao.java` | DAO 类异常降级策略注释、方法 null 语义声明 |

### 1.4 核心约束

- **仅优化/补全注释**：只增删注释行与 Javadoc 块，**不改变任何代码 token、签名、缩进、变量名、注解、线程/并发/扫描核心逻辑**。
- 整改后 `mvn clean test` 全绿。
- 不引入新依赖。

## 二、通用注释总则

### 2.1 核心原则

> **注释解释"为什么"，代码展示"做什么"。**

- 坏例：`i++; // i 加 1`
- 好例：`// 重试一次，规避 DNS 瞬时抖动`

只注释以下内容：业务逻辑意图、特殊场景约束、风险点提示、并发安全纪律、性能权衡、Burp API 行为特性。禁止逐字复述代码、禁止无意义冗余注释。

### 2.2 语言规范

- 统一**中文为主**，与项目既有优质注释一致。
- **技术术语保留英文原词**，不在同一句内中英混译。保留英文的术语包括但不限于：

| 类别 | 保留英文术语 |
|------|-------------|
| 线程/并发 | EDT、volatile、synchronized、invokeLater、ThreadFactory、RejectedExecutionException、ForkJoinPool |
| 安全/漏洞 | WAF、payload、SQL 注入、DNSLog、JNDI、fastjson、log4j、XSS、SSRF |
| 缓存/限流 | LRU、TTL、cache、throttle |
| 数据/协议 | HTTP、URL、Header、Cookie、charset、chunked、Base64 |
| 存储 | SQLite、JDBC、PreparedStatement、ResultSet |
| UI | Swing、JTable、JPanel、JSplitPane、GridBagLayout、BorderLayout |
| Burp | IBurpExtenderCallbacks、IHttpListener、IContextMenuFactory、makeHttpRequest、buildHttpMessage |

- **彻底消除中英混用问题**：禁止 `// 并发的 concurrent 线程池` 式混译。

### 2.3 标签规范

- **全局禁止 `@Author`、`@Date` 冗余标签**（git blame 可查）。
- 历史残留的 `@Author Xm17` / `@Date 2024-06-21 15:39` 在整改时统一删除。
- `@param` / `@return` / `@throws` 按第四章规范使用，不滥用。

### 2.4 格式规范

#### Javadoc 标准格式

```java
/**
 * 一句话职责概述（独立完整句，以句号结尾）。
 *
 * <p>可选补充段：线程模型 / 锁纪律 / 生命周期 / 与其他类的关系。</p>
 */
```

- Javadoc 块内**禁止空行冗余**（禁止每行之间插入空行，如 `GridBagConstraintsHelper` 旧风格）。
- 块内换行紧跟内容，不产生连续空行。

#### 分区注释

长文件/长方法使用统一分区注释：

```java
// ================ 分区名 ============
```

与 `SqlUI`、`Utils` 既有风格一致。分区名用中文短语（如"文件操作相关""URL处理相关""字符串处理相关"）。

#### 行内注释

- 默认放在被解释代码**上方**；仅短说明（≤20 字符）可放行尾。
- 行尾注释与代码间留一个空格：`code // 注释`。
- 禁止字段区每个字段都跟行尾注释（如 `SqlUI` 旧风格），改用上方行内注释或合并到字段声明上方一段说明。

### 2.5 注释边界

| 场景 | 是否注释 | 说明 |
|------|---------|------|
| 自明 getter/setter | 否 | `getId()` / `setId()` 无需注释 |
| 无逻辑空构造器 | 否 | `public AuthBean() {}` 无需注释 |
| 核心业务方法 | 是 | 扫描、检测、UI 初始化、事件处理 |
| 并发方法 | 是 | synchronized / volatile / invokeLater / 线程池提交 |
| 数据库操作 | 是 | DAO 层所有 public static 方法 |
| UI 渲染/刷新 | 是 | 表格模型刷新、编辑器设置、布局构建 |
| 检测判定逻辑 | 是 | 漏洞检测原理、规则匹配、误报规避 |
| private 方法 ≤10 行且自明 | 否 | 方法名完整表达意图 |
| private 方法 >10 行或逻辑复杂 | 是 | 一行短注释说明意图 |

### 2.6 注释生命周期

- 改逻辑必须同步改注释，过期注释比没有注释更害人。
- 删代码必须删对应注释。
- 禁止死代码注释（被注释掉的代码块直接删除，git 历史可查），唯一例外是解释"为什么不采用某方案"。
- 禁止裸 `TODO`；确需保留时写明原因：`// TODO(原因): 说明`。

## 四、Javadoc 标签统一使用规范

### 4.1 `@param`

- 仅用于**不自明**的入参：业务含义非直觉、有取值约束、可能为 null 或非空。
- 参数名自明时不写 `@param`（如 `getUrl(URL url)` 不写 `@param url URL`）。
- 格式：`@param name 业务含义说明`，说明必须包含业务语义。

```java
/**
 * @param module 配置模块名（如 "sql"、"tool"、"config"）
 * @param type   配置类型键（如 "payload"、"header"）
 */
```

### 4.2 `@return`

- 描述返回结果的业务含义、空值语义、数据结构含义。
- 自明返回值（如 `boolean isEmpty()` 返回是否为空）可省略。
- 必须标注的 `@return` 场景：
  - 返回 null 的方法（如"无匹配返回 null"）
  - 返回空列表/空对象的方法（如"异常时返回空列表"）
  - 返回值有特殊含义（如"-1 表示未找到""false 表示队列满"）

### 4.3 `@throws`

- 标注方法**主动抛出**或**可能抛出**的异常类型、触发场景。
- DAO 层方法因统一 catch + 降级，**不抛出受检异常**，无需 `@throws`。
- `ThreadManager.submit()` 等可能抛 `RejectedExecutionException` 的方法必须标注。

### 4.4 禁止项

## 九、验收标准

### 9.1 注释完整性

1. 每个 `public`/`protected` 类有职责概述 Javadoc，首句为独立完整句。
2. 每个 `public`/`protected` 方法有行为说明 Javadoc。
3. DAO 层所有 `public static` 方法有操作类型 + 返回值/null 语义。
4. UI 层每个类（含 Entry/Model/Table）有类级注释。
5. 工具类标注线程安全语义。

### 9.2 注释规范性

1. 无死代码注释、无空 Javadoc（`/** */`）、无裸 `TODO`。
2. 无 `@Author` / `@Date` 残留标签。
3. 无逐字复述式注释。
4. 无中英混用（统一中文为主，技术术语保留英文原词）。
5. Javadoc 块内无空行冗余。
6. 字段区无行尾密集注释。

### 9.3 特殊场景覆盖

1. 并发点（`synchronized` / `volatile` / `invokeLater` / 线程池）均有纪律注释。
2. 魔法数（`MAX_*` / `*_TTL_MS` / `*_INTERVAL_MS` / `POOL_SIZE`）有来源注释。
3. DAO 方法有异常降级策略注释。
4. 被动扫描方法有监听触发条件 + 工具来源过滤注释。
5. 检测判定方法有判定原理 + 阈值来源注释。

### 9.4 行为不变

1. 注释与代码无行为偏差。
2. 未修改任何代码 token、签名、缩进。
3. `mvn clean test` 全绿。
